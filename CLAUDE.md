# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A video → anime converter modelled on Corridor Crew's *Anime Rock Paper Scissors*. Python drives a local ComfyUI server over its HTTP API. `plan.md` holds the full 7-stage architecture and 6-phase roadmap (ingest → preprocess → conditioning → stylize → temporal → composite → encode, plus an offline LoRA training track). **Phases 1 to 4 are built**: the single-image img2img + anime-lineart ControlNet test, a resumable frame pipeline (`cli.py`: ingest → per-frame img2img → encode, in `pipeline/video.py` and `pipeline/batch.py`), and phase 3, which makes frames agree. Phase 3 has two parts: a flow-warp deflicker (`cli.py deflicker`, `pipeline/temporal.py`, OpenCV Farneback flow on the CPU, config `temporal:`; `temporal.mode` is `recursive`, blending with the previous output, or `median`, the per-pixel median of `radius` frames on each side warped onto the frame, which is steadier and is what `config/project.yaml` uses) and a cloud stage (`cli.py animatediff`, `pipeline/animatediff.py`, `workflows/animatediff_lineart_api.json`, `notebooks/kaggle_animatediff.ipynb`, guide `docs/cloud-kaggle.md`) that runs a whole shot through AnimateDiff in one pass on a Kaggle GPU. On both test clips AnimateDiff + deflicker was the steadiest (`docs/phase3-guide.md`). IP-Adapter is optional and off by default (`animatediff.ip_adapter.enabled`; it did not help). RAFT flow was tried in the deflicker and not kept. The cloud graph needs ComfyUI-Advanced-ControlNet (the stock ControlNet nodes fail with AnimateDiff's sliding windows). Tests live in `tests/` (phases 2 to 4, 67 tests; there is no linter). **Phase 4 (LoRA training) is built** except for `cli.py train`: `training/extract_style.py` + `pipeline/style_frames.py` pull style frames from a film into `training/data/style/images/`; actor photos go in `training/data/actors/<name>/` (`training/README.md`); `training/caption.py` + `pipeline/captioning.py` convert actor photos, add face and upper-body crops (`pipeline/photo_crops.py`) and write WD14 captions; `scripts/setup_training.py` + `training/train.py` + `pipeline/lora_train.py` train LoRAs locally with kohya sd-scripts (`third_party/sd-scripts`, separate `.venv-train`, 6 GB settings, about 33 min per LoRA); `training/eval_grid.py` + `pipeline/lora_eval.py` render a comparison grid per LoRA (results in `docs/phase4-results.md`); `style.loras` in the config (each entry's `file:` is the path to the .safetensors, relative to the project root or absolute, and the name defaults to its file name; `style_record()` leaves the path out of a shot's recorded settings, so moving a file is not a changed setting) chains `LoraLoader` nodes into the img2img graph (`apply_loras()` in `pipeline/stylize.py`, nodes "20" and up; env var `ANIME_CONFIG` picks another config file); the AnimateDiff cloud graph, bundle and notebook carry the `style.loras` too (`apply_loras(..., model_node=)` in `pipeline/animatediff.py`; the bundle stores the files under `loras/`, notebook step 3 copies them into ComfyUI), and `cli.py train` is not built. Phase 4's measured outcome (`docs/phase4-results.md`): the **style** LoRA works and is on by default; the **actor** LoRA is off, because trained on real photos it pulls the face back to photographic; AnimateDiff dilutes a style LoRA, so for a close-up face the local per-frame path beats the cloud pass; and the deflicker needs `temporal.lowpass_sigma: 8` on a face (2 drags the cel shading along the optical flow and smears it). Stronger recursive deflicker (strength 0.97, sigma 16 or 24) is no steadier; the median mode is (SSIM ratio 0.893 -> 0.939 on `full_D`), but a glasses colour that stays red for several frames survives it, since that comes from the generator. Jaw-word and glasses/skin-word prompt experiments cost image quality and are not in the config (`docs/phase4-results.md`). Not started: phase 5 (matting, compositing, face pass) and phase 6 (web UI), so don't assume they exist.

## Commands

Windows / PowerShell. Always use the project venv (Python 3.11); the system default `python` is 3.15, which PyTorch doesn't support.

```powershell
scripts\start_comfyui.ps1                                  # ComfyUI server on 127.0.0.1:8188 (blocks; run in its own terminal/background)
.venv\Scripts\python.exe scripts\test_single_frame.py [image] [--denoise 0.45] [--seed 1]   # outputs to work/phase1/
.venv\Scripts\python.exe scripts\download_models.py        # idempotent; fetches checkpoint, ControlNet and netG.pth into third_party/ComfyUI
.venv\Scripts\python.exe cli.py preview [video] [--start 5 --seconds 4]   # defaults from config `input:`; 15 to 18 s/frame; output work/default/out/<shot>.mp4
.venv\Scripts\python.exe cli.py                      # no command = `run` with the config's input (IDE run button)
.venv\Scripts\python.exe cli.py run [video]                # config's slice (`seconds: null` = whole clip); re-run to resume
.venv\Scripts\python.exe cli.py flicker <shot>   # flicker: whole-frame SSIM, static-region change and color steadiness (lower = steadier); --frames N
.venv\Scripts\python.exe cli.py deflicker [shot] [--source animatediff]   # phase 3 local deflicker (CPU) -> deflicker[_animatediff]/<shot>
.venv\Scripts\python.exe scripts\make_cloud_bundle.py [shot] [--set KEY=VALUE]  # zip for the Kaggle notebook (docs/cloud-kaggle.md); cli.py animatediff itself only runs on a 16 GB GPU
.venv\Scripts\python.exe cli.py flicker <shot> --stage animatediff|deflicker|deflicker_animatediff   # measure a phase 3 stage; also prints color flicker/drift
.venv\Scripts\python.exe -m pytest tests -q    # 67 tests (phases 2 to 4); no GPU or ComfyUI needed
```

Full from-scratch setup is in `README.md`. `docs/how-to-run.md` is the user's run reference (IDE and command prompt, per phase, settings, troubleshooting) with a change log: **update it, including the change log, whenever you add or change anything that affects how the project is run**. A single-frame run takes about 40 s on the RTX 2060 (6 GB). `docs/phase1-guide.md` maps every model file to the workflow node that loads it and lists what phase 1 still has pending; keep it in sync when models or nodes change. `docs/phase3-guide.md` covers phase 3 (the deflicker, the Kaggle AnimateDiff stage, tuning and all results); update it when those settings or results change, and `docs/cloud-kaggle.md` when the notebook or bundle steps change. `docs/phase2-results.md` covers the frame pipeline, the flicker baseline and known issues; update it when phase 3 changes the baseline. `docs/phase4-results.md` covers the LoRAs: training runs, the grids, the ablation that put the actor LoRA aside, the tuned selfie settings, the cloud comparison and the deflicker fix; update it when LoRA settings or results change, and `training/README.md` when the data layout changes.

## Architecture

- **`pipeline/comfy_client.py`** is the only thing that talks to ComfyUI: `upload_image` → `queue` → `wait` (polls `/history`, no websocket) → `download_outputs`. `run()` chains them. Outputs come back as `{node_id: [paths]}`; an optional `names={"12": "anime/frame_00001.png"}` saves them under your own names instead of ComfyUI's counter names. Future stages should call ComfyUI through this client.
- **Phase 2 frame pipeline:** `cli.py` (`preview`, `run`, `flicker`) → `pipeline/video.py` (ffmpeg `extract_frames` / `encode`, audio muxed from the source) → `pipeline/batch.py` (`stylize_shot`, one `ComfyClient` round trip per frame, skips frames whose `anime/<shot>/frame_*.png` exists). `pipeline/metrics.py` holds the flicker metrics (whole frame, and static regions where the source doesn't move; compare runs over the same frames) and `pipeline/vram.py` prints the run's peak GPU memory (measured: 5399 of 6144 MiB, so AnimateDiff does not fit locally and runs on Kaggle). Video, start, seconds and shot name come from the config's `input:` section (`shot` falls back to the video's file name, plus `_preview` for `preview`); CLI options override it.
- **ComfyUI is started on demand:** `pipeline/server.py` (`comfy_server`) uses a running server if there is one, otherwise starts `scripts/start_comfyui.ps1` hidden (on Linux, `python main.py` in `third_party/ComfyUI`), waits, and stops it afterwards if it started it (`comfyui.autostart` / `autostop` in the config). `stylize_shot`, `animatediff_shot` and `test_single_frame.py` use it, and `stylize_shot` skips it when no frame is left to do. The user wants every entry point runnable from the IDE with no terminal step, so new scripts should take no required arguments, and each needs a `.vscode/launch.json` entry.
- **Resume and settings tracking:** `pipeline/shot_state.py` writes a `settings.json` into `frames/<shot>` (video, size, mtime, start, seconds, fps) and `anime/<shot>` (effective seed and denoise, sampling, style, models, ControlNet, megapixels, plus the frames' own settings). Later stages (`deflicker/`, `animatediff/`, `deflicker_animatediff/`) record their own settings plus those of the stage they read, under the same rule. Same settings: finished frames are skipped (resume). Changed settings, or a shot made before tracking (no `settings.json`): the run stops with `SettingsChanged` (exit code 1, a message naming what changed) before deleting, overwriting or encoding anything. There is deliberately no force flag, so a shot can't be overwritten by accident: set a new shot name (`input.shot` in the config, or `--shot`). Shots in `work/` made before tracking (`dance_preview`, `dance_d040`, `verify_d040`, `verify_msg`) have no record and are locked the same way; `dance_d040` is the phase 2 baseline.
- **`workflows/*.json`** are ComfyUI *API-format* graphs, not UI-format ones. Re-export from ComfyUI with "Save (API Format)".
- **Workflows are patched by hard-coded node id** in `pipeline/stylize.py` (`build_workflow()` sets `wf["10"]` for the KSampler, `wf["4"]`/`wf["5"]` for the prompts, and so on). `scripts/test_single_frame.py` and `pipeline/batch.py` call it. If you renumber or add nodes in a workflow JSON, update `build_workflow()` and the `ANIME_NODE`/`LINEART_NODE` constants. `workflows/img2img_lineart_api.json` has both a final `SaveImage` (`anime`) and a debug one for the lineart map (`lineart`). The AnimateDiff graph is patched the same way by `build_workflow()` in `pipeline/animatediff.py` (node 2 frames folder, 7 lineart size, 10 sampler, 17 and 18 AnimateDiff, 14 to 16 IP-Adapter, which the code deletes when it is off).
- **The script runs the JSON file, not whatever graph is open in the ComfyUI browser UI.** The UI's default template (it uses a `qwen_3_4b` CLIP and different sampler values) is unrelated to our workflow, and its "missing model" warning can be ignored. Our graph has no `CLIPLoader`: UNet, CLIP and VAE all come from the one checkpoint loaded by node `"1"`, so `models/clip` and `models/vae` are empty on purpose.
- **Model files:** the checkpoint, ControlNet and `netG.pth` (the lineart extractor weights, about 208 MB) are all fetched by `scripts/download_models.py`. Its `FILES` paths are relative to `third_party/ComfyUI`, since `netG.pth` goes under `custom_nodes/comfyui_controlnet_aux/ckpts/`, not `models/`. `download_models.py --cloud` also fetches the AnimateDiff motion module and, only if IP-Adapter is enabled, its models.
- **Lineart map size:** the preprocessor's `resolution` sets the map's *short side*. `build_workflow()` in `pipeline/stylize.py` computes the short side node `"3"` produces and writes it into node `"7"`, so the map matches the frame. The JSON's `512` is only a placeholder; always build the graph through `build_workflow()` (phase 2's batch loop included).
- **`config/project.example.yaml`** is the single source of tunables (input video/start/seconds, models, prompts, seed, denoise, ControlNet strength, `target_megapixels`). Code reads `config/project.yaml` first (a complete copy, not merged with the example), then falls back to the example. `project.yaml` is in git and holds the selfie setting "D" (`my video new.MOV`, shot `full_D`, style LoRA 0.6, denoise 0.6, ControlNet 1.0 so the face follows the source, no jaw/glasses/skin words, actor LoRA off, deflicker `mode: median`, radius 3, `lowpass_sigma: 2`, error threshold 25); "A" was the same with ControlNet 0.8; the example keeps the original defaults (denoise 0.4, sigma 2), so the two differ on purpose. The user's own footage (`my video new.MOV`) is deliberately **not** committed: the GitHub repo is public.
- **Tests** (`pytest tests -q`) fake ComfyUI and use real ffmpeg on a generated clip, so they run without a GPU or server. `samples/dance/dance.webm` is the real test clip (CC BY 3.0, ThierryTuyishimeTV); `samples/capetown/capetown_dance.webm` (CC BY-SA 4.0, 23Faerie) is a harder handheld-camera second clip, used as shots `capetown_run1` (4 s from 8 s) and `capetown_pan1` (4 s of fast pans from 13 s). Stylizing is about 15 to 18 s/frame, so keep previews short.
- **`third_party/ComfyUI`** is an upstream checkout (plus the `comfyui_controlnet_aux` custom node). Treat it as vendor code; don't edit it. Its contributor `AGENTS.md` applies only to changes to ComfyUI itself.
- Design intent to preserve: stages read and write `work/<project>/<stage>/<shot>/frame_%05d.png` so they're resumable, and a fixed seed and prompt per shot limit flicker. Stylization targets 12 fps and about 0.4 MP, which is the 6 GB VRAM budget (SD1.5; SDXL, video models and the AnimateDiff pass are cloud-only).

## Environment gotchas

- **PATH in new shells:** winget installs (git, ffmpeg) aren't on PATH in the tool shell until you refresh it: `$env:Path = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")`. `start_comfyui.ps1` already does this.
- **`OSError: WinError 1114` loading `c10.dll`** means the Visual C++ Redistributable is too old. Upgrade `Microsoft.VCRedist.2015+.x64`.
- **Don't `pip install -r` the controlnet_aux requirements.txt wholesale.** It pulls `mediapipe`/`onnxruntime-gpu`, which can pin numpy below 2 and break the torch stack. Install only the deps the specific preprocessor needs (the current minimal set is in `README.md`).
- `.venv/`, `third_party/` and `work/` are generated or vendored. The project is a git repo (branch `main`, remote `origin` on GitHub); those three folders are in `.gitignore`, as is `result_*/` (unzipped cloud results).
- **The Kaggle notebook runs the code in the uploaded dataset, not this checkout.** After changing code the cloud stage uses, rebuild the bundle and upload it as a new dataset version, or the notebook keeps running the old code.
- **A running ComfyUI never sees custom nodes installed after it started.** Restart it (the notebook's step 4 starts a fresh one); `animatediff_shot` names any missing nodes before queueing.
- **Commits:** don't commit or push unless the user asks for it in that request. Finish the work, then offer.
